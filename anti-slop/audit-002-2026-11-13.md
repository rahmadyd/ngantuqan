# antislop audit 002 — ngantuqan (bilingual layer)

- **Date:** 2026-11-13
- **Mode:** after (session override)
- **Scope:** the English/Indonesian language toggle and the bilingual content layer. Public site plus the admin surface that edits the translated content.
- **Direction read:** `DESIGN.md` (no visual change was made; the toggle had to fit the existing header).
- **Method:** `npm run build`, `npm run typecheck`, `npm run lint`, then Playwright passes at 1440x900 and 390x844 in both locales, plus a text dump of every public route in Indonesian to prove nothing was left in English.
- **Data:** local Supabase stack (`supabase_db_ngantuqan`). Migrations 0014, 0015 and 0016 were applied and every seeded row was given its Indonesian wording.

**Nothing in `src/` was modified by this audit.** Findings are listed for the owner to approve by number.

### Step verification

**Locale plumbing**
- The language is read from the `ngantuqan_locale` cookie on the server, so `<html lang>` is right in the first byte of HTML rather than patched in the browser.
- The toggle writes the cookie and asks the server to render again. The whole page, including the content from the database, arrives in that language.
- `src/app/layout.tsx` carries the `LocaleProvider`, so the root error boundary and the 404 page can translate too. The provider used to live in the public layout, where a root-level error had no access to it.

**Content layer**
- One row per record. The English text stays on the row and the Indonesian wording sits beside it in a `translations` JSONB column, so a half-translated record still reads in English rather than disappearing from the Indonesian page.
- Columns added: `categories`, `projects`, `services`, `service_packages`, `products`, `testimonials`, `project_images`, `product_images`. The site settings keep theirs under `studio.translations`.
- Every seeded row in the local database now carries its Indonesian wording: 11 categories, 6 projects, 11 service packages, 5 services, 6 products, 4 testimonials, 11 project images, 7 product images, 1 studio settings row.

**Admin**
- Every translatable field carries a second input named `tr_id_{field}`. The English input keeps its place; the Indonesian one sits directly beneath it, separated by a border, so the studio can tell them apart.
- The admin action merges the submitted Indonesian wording with the translations already on the row, so a translation in another language is never lost by an edit.
- The gallery editor gained a second alt-text field for the same reason.

**Measured results**
- Route sweep, English and Indonesian, desktop and mobile: 92/92 PASS. Every route returns its own status, exactly one `<h1>`, no horizontal overflow, no console errors, and `<html lang>` matching the chosen locale.
- Click-through, English: 24/24 PASS, 0 console errors.
- Click-through, Indonesian: 20/20 PASS, 0 console errors.
- The toggle flips the page in both directions from either starting language, on desktop and on mobile.
- Text dump of eleven public routes in Indonesian: every visible string is Indonesian. The only English left is brand names, file-format codes and the legal bodies (L-09).
- `npm run typecheck` PASS, `npm run lint` PASS (0 errors, 0 warnings), `npm run build` PASS.

## L-09 - The legal bodies are English by decision, not by accident

- **Component:** privacy policy, terms and conditions, refund policy, digital product licence
- **File:** `src/app/(public)/privacy-policy/page.tsx`, `terms-and-conditions/page.tsx`, `refund-policy/page.tsx`, `digital-product-license/page.tsx`
- **Problem:** the chrome on the four legal pages is translated, but the body of each document is still English. A visible note says so, using `t.common.notTranslated`, so no visitor is misled.
- **Rule:** R-23 (no invented content). Translating a legal document without a lawyer would be writing legal text the studio has not reviewed.
- **Status:** **open.** Needs an Indonesian lawyer and the studio's approval of the wording. The note on each page can be removed once the translation is in place.

## L-10 - The admin dashboard and the admin sign-in stay English

- **Component:** `/admin`, `/admin-login`
- **File:** every page under `src/app/admin/`
- **Problem:** the studio's own dashboard is English-only. The labels, the validation messages and the action results are all English.
- **Rule:** not an antislop rule. The request was for the public site to be bilingual; the admin is the studio's tool, not a visitor surface.
- **Status:** **open.** The owner may want the dashboard in Indonesian as well. The dictionary is already in place, so it would be a similar job to the public one, but it is a second scope.

---

## Note on the method

The first copy of this audit reported that the Indonesian pages still read in English. That was wrong: the test read the cookie with a PowerShell `Invoke-WebRequest`, which drops the `Cookie` header. The same page served the Indonesian content correctly over `curl` and in the browser. The copy checks were rewritten to read the rendered page in a real browser context, where the cookie is applied by the browser rather than by the test harness. The 92/92 result above is from that corrected pass.

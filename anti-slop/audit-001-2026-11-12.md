## HIGH — Hard Gate

### V-01 — Focus ring is invisible on the two dark panels
- **Component:** CTA section, site footer
- **File:** `src/app/globals.css:134`, `src/components/home/home-cta.tsx:6`, `src/components/layout/site-footer.tsx:24`
- **Problem:** the base focus rule is `outline: 3px solid var(--text)` (`#20243A`). Both the CTA panel and the footer use `bg-text` (`#20243A`). Measured with real keyboard Tab: the CTA ghost link "See what we offer" and the footer email link `hello@ngantuqan.studio` resolve to `outline-color: rgb(32, 36, 58)` on a `rgb(32, 36, 58)` background. The ring is the same colour as the surface it sits on. Footer nav links behave differently (they inherit a light ring), so the behaviour is inconsistent as well as invisible.
- **Rule:** R-32 (visible focus indicator), R-39 (affordances)
- **Improvement:** make the focus ring surface-aware. Add a `--focus-ring` token that is `--text` on light surfaces and `--background` on dark ones, then set it on the CTA and footer surfaces. One token, no layout change.

### V-02 — Every button in the app shows the arrow cursor
- **Component:** all `<button>` elements (menu trigger, work/shop filters, form submit)
- **File:** `src/app/globals.css:102` (no base rule exists)
- **Problem:** the project CSS contains no base-layer cursor rule. `a[href]` picks up `cursor: pointer` from the browser UA stylesheet, but `<button>` does not. Measured on three routes: "Open menu", "All work", the five category filters, "Send message" all compute `cursor: default`. Filters and submit buttons therefore read as static text until hovered.
- **Rule:** R-39 (`cursor: pointer` set once in the base CSS layer)
- **Improvement:** add one base-layer rule covering `a[href]`, `button:not(:disabled)`, `summary`, `select`, `label[for]`, `[role=button]`, `[role=tab]`, `[role=switch]`. Pure CSS, no component edits.

### V-03 — The hero publishes three numbers that do not match the data
- **Component:** homepage hero, stat row
- **File:** `src/components/home/hero-section.tsx:43-62`
- **Problem:** "Services 5", "Avg. delivery 7 days", "Revisions 2-4" are typed literals. The service turnaround values in `src/lib/data/demo.ts` are 5, 4, 14, 7 and 21 days (mean 10.2, not 7), and the revision policies read "2 revision rounds included", "3 revision rounds on the mark" and "2 revision rounds per stage" (no 2-4 range). Two of the three figures contradict the studio's own catalogue.
- **Rule:** R-17 (numbers without a real source), R-36 (fabricated claims)
- **Improvement:** derive the figures from the live service query, or drop the row. If a stat row survives the refresh it must be computed, not typed.

### V-04 — Em dash in user-facing copy
- **Component:** page copy, form labels and placeholders, validation messages, transactional email subjects and bodies, metadata titles
- **File (representative):** `src/app/layout.tsx:30,31,34`, `src/app/(public)/page.tsx:18,20`, `src/app/(public)/contact/page.tsx:28`, `src/app/(public)/services/page.tsx:9,29`, `src/app/(public)/about/page.tsx:100,101,122`, `src/app/(public)/shop/[slug]/page.tsx:212`, `src/app/(public)/order/[service-slug]/page.tsx:89`, `src/app/(public)/order/[service-slug]/submitted/page.tsx:86`, `src/app/(public)/order-confirmation/[orderNumber]/page.tsx:176`, `src/app/(public)/digital-product-license/page.tsx:43`, `src/app/error.tsx:30`, `src/components/home/hero-section.tsx:29`, `src/components/home/selected-works.tsx:18`, `src/components/home/services-overview.tsx:14`, `src/components/home/studio-intro.tsx:19`, `src/components/forms/contact-form.tsx:163`, `src/components/forms/order-brief-form.tsx:207,210,254,387,411`, `src/components/shop/cart-link.tsx:24`, `src/components/shop/checkout-form.tsx:248`, `src/components/shop/download-button.tsx:60`, `src/components/shop/order-access-form.tsx:72`, `src/components/layout/site-header.tsx:16`, `src/lib/validations/contact.ts:40`, `src/lib/validations/order.ts:36`, `src/lib/actions/inquiries.ts:132,133`, `src/lib/email/send.ts:212,261,267,310,348,401,445,450,467,473,498`
- **Problem:** the em dash character is used in roughly 30 strings a visitor reads, including the hero lede ("small teams - then hand over the tools"), every `<option>` in the brief form, the "Send message" success copy, and the subject line of every customer email.
- **Rule:** R-02
- **Improvement:** replace with a comma, period, colon or parentheses. Code comments are out of scope for R-02 and can stay. The `DEMO -` prefixes in `src/lib/data/demo.ts` are seed content, not agent copy, and can stay under R-37.

### V-05 — Disabled controls have no `not-allowed` cursor and no `aria-disabled`
- **Component:** Button, ButtonLink
- **File:** `src/components/ui/button.tsx:6`, `src/components/ui/button-link.tsx:58`
- **Problem:** `disabled:pointer-events-none disabled:opacity-45` removes the element from the hit test entirely, so `cursor: not-allowed` can never be shown. The design system requires `cursor: not-allowed` plus `aria-disabled` on disabled controls (`docs/05-design-system.md` §5.11). Neither is present.
- **Rule:** R-39, R-26
- **Improvement:** drop `pointer-events-none`, add `disabled:cursor-not-allowed`, and add `aria-disabled` where the control must stay focusable.

## MEDIUM — Purpose-Gate

### V-06 — The hero has no visual anchor
- **Component:** homepage hero
- **File:** `src/components/home/hero-section.tsx:18-26`
- **Problem:** the hero is a single left-aligned text column inside `max-w-4xl`. Measured at 1440px: the section is 746px tall and the text occupies 640px of the 1320px container, leaving roughly 800px of empty cream to the right. The editorial grid in `docs/05-design-system.md` §5.6 specifies a 7/5 text/visual split for the hero, but no visual exists. The section reads as an unfinished draft rather than a composition.
- **Rule:** R-20 (visual identity), R-05, Part 3 Levers (one focal point per screen)
- **Improvement:** rebuild the hero as the authorised 7/5 split with an original Mediterranean-motif illustration on the right. This is the one section where structure may change.

### V-07 — Work, product and service cards share one identical anatomy
- **Component:** ProjectCard, ProductCard, ServiceCard
- **File:** `src/components/portfolio/project-card.tsx:20-90`, `src/components/shop/product-card.tsx:19-91`, `src/components/services/service-card.tsx:33-112`
- **Problem:** all three use the same shell: `rounded-lg border border-border bg-surface shadow-sm`, the same `hover:-translate-y-0.5 hover:shadow-md`, the same `p-6` body, the same `font-display` title, the same `text-sm text-muted line-clamp-3` description, the same trailing "label + ArrowUpRight" affordance. Nothing tells a visitor that a portfolio piece, a purchasable template and a bookable service are different kinds of thing.
- **Rule:** R-14 (identical feature cards), R-05 (uniform section rhythm), Part 3 RHYTHM dial
- **Improvement:** differentiate by visual treatment only. Work stays image-first and editorial, products lead with price, services lead with the accent colour. Grid, order and content placement stay as they are.

### V-08 — An arrow decorates almost every button and link
- **Component:** hero CTA, section header buttons, inline text links, all three card types
- **File:** `src/components/home/hero-section.tsx:36`, `src/components/home/selected-works.tsx:22,49`, `src/components/home/studio-intro.tsx:30,57`, `src/components/portfolio/project-card.tsx:84`, `src/components/shop/product-card.tsx:76`, `src/components/services/service-card.tsx:104`
- **Problem:** the ArrowUpRight / ArrowRight glyph appears on the primary hero CTA, on every section "View All" button, on every inline text link and on every card. It carries no information and is the default AI-button flourish.
- **Rule:** R-08
- **Improvement:** keep the arrow only where it signals a genuine destination change (card to detail page). Drop it from the hero primary CTA and the inline links, and let the hover state carry the affordance instead.

### V-09 — Icons come from one default library and several are pure decoration
- **Component:** testimonials, services, products, navigation
- **File:** `src/components/home/testimonials.tsx:1,23`, `src/components/services/service-card.tsx:3,78,84`, `src/components/shop/product-card.tsx:2,85`, `src/components/portfolio/project-card.tsx:3,84`, `src/components/layout/site-nav.tsx:6`
- **Problem:** the whole icon language is Lucide thin-stroke. The `Quote` glyph on testimonials and the universal ArrowUpRight carry no content meaning; `Clock` and `RefreshCw` do name real concepts.
- **Rule:** R-04 (icon set chosen for its library look, not for relevance)
- **Improvement:** keep the icons that name something (file format, cart, turnaround, revisions). Remove the purely decorative Quote mark. If the identity needs a motif, draw a small original SVG set from the Mediterranean motifs in `DESIGN.md` §9 rather than reaching for the library default. Any new artwork needs owner approval first (R-23).

### V-10 — Every service card carries a badge that repeats the section title
- **Component:** ServiceCard
- **File:** `src/components/services/service-card.tsx:59`
- **Problem:** all five cards render a capsule reading literally "Service", under a heading that already says "What We Do" and "Five ways we can help". The card also carries a second, coloured accent dot on the cover image, so the same signal is given twice. The badge is a capsule with no functional payload.
- **Rule:** R-09 (badges must be functionally needed), R-31 (reason)
- **Improvement:** remove the redundant "Service" badge and keep one meaningful signal, the coloured cover accent. No change to the card grid.

### V-11 — Four brand accents compete inside one viewport
- **Component:** Services Overview, Why Work With Us, Studio Intro, navigation, eyebrows
- **File:** `src/app/globals.css:10-17`, `src/components/services/service-card.tsx:8`, `src/components/home/why-work-with-us.tsx:3-24`, `src/components/home/studio-intro.tsx:35-39`
- **Problem:** the live palette is blue, yellow, coral and mint plus cream and ink. On one homepage scroll the Services section rotates four accents across five cards, Why Work With Us adds four more accent dots, Studio Intro adds a mint blob and a coral dot, and the coral eyebrow rule plus the coral nav underline repeat on every section. Four accents are competing at once. `docs/05-design-system.md` §5.3 contradicts its own Principle 1 ("one accent colour per viewport region, a page never shows all four accents competing") and exceeds the R-29 limit of two or three core colours plus one accent.
- **Rule:** R-29, R-01
- **Improvement:** pick one hero accent and demote the rest to supporting roles in a single region each. `DESIGN.md` §3 points at bougainvillea pink as the accent, which would also give the coral motif a single job.

### V-12 — The primary button is the AI-default blue on a warm cream canvas
- **Component:** Button / ButtonLink primary variant, hero CTA, header CTA
- **File:** `src/app/globals.css:12`, `src/components/ui/button.tsx:11`, `src/components/ui/button-link.tsx:18`
- **Problem:** `--primary: #4263EB` is a saturated royal blue. On a warm cream canvas it reads as a foreign element dropped into the page rather than a brand colour, and it is the single loudest thing on the homepage. `DESIGN.md` §3 specifies Mediterranean Blue `#3687D8` and Cobalt `#175BE5` instead, neither of which is currently in the codebase.
- **Rule:** R-01 (neon blue button as a default without purpose)
- **Improvement:** move the primary token to the `DESIGN.md` value, which is a one-token change in `globals.css` and repaints every button, link and focus accent at once.

### V-13 — Shadow is applied to everything
- **Component:** all cards, all buttons, the shared Card primitive
- **File:** `src/components/ui/card.tsx:11`, `src/components/portfolio/project-card.tsx:22`, `src/components/shop/product-card.tsx:21`, `src/components/services/service-card.tsx:35`, `src/components/ui/button.tsx:11-19`, `src/components/ui/button-link.tsx:18-27`
- **Problem:** `shadow-xs` sits on every button and `shadow-sm` on every card at rest, with `hover:shadow-md` on every card. Shadow is no longer an elevation signal; it is a default on 30-plus surfaces, which is exactly the "everything floats" tell.
- **Rule:** R-12
- **Improvement:** reserve shadow for genuinely raised things (mobile nav panel, dropdown, hover-lifted card) and let the 1px hairline border carry flat cards.

### V-15 — Public pages have no loading state
- **Component:** work and shop filter bars, all public routes
- **File:** `src/app/(public)/work/page.tsx:62`, `src/app/(public)/shop/page.tsx:70`, `src/app/(public)/layout.tsx:13`

The only Suspense fallback in the public surface is `<div className="h-24" />`, a blank 96px strip rather than a skeleton. The admin has `src/app/admin/loading.tsx`; the public surface has no equivalent.
- **Rule:** R-27 (every data view needs empty, loading and error states)
- **Improvement:** add a skeleton that matches the final filter-bar dimensions, and a route-level `loading.tsx` for the public group. The shared `Skeleton` primitive already exists in `src/components/ui/feedback.tsx:25`.

### V-16 — Four of eight homepage sections share one composition
- **Component:** Selected Works, Products Preview, Why Work With Us, Testimonials
- **File:** `src/components/home/selected-works.tsx:14-24`, `src/components/home/products-preview.tsx:13-23`, `src/components/home/why-work-with-us.tsx:30-34`, `src/components/home/testimonials.tsx:11-16`

- **Improvement:** give coral one job (brand punctuation, per `DESIGN.md` §3 "decorative accents and highlights") and move the functional signals to the ink or the neutral surfaces.

### V-21 — No light/dark toggle
- **Component:** site-wide
- **File:** `src/app/layout.tsx:58-61`
- **Problem:** `colorScheme` is pinned to `"light"` and no toggle exists. R-21 requires either a branding reason for a fixed theme or a working toggle.
- **Rule:** R-21
- **Improvement:** the defensible answer here is a fixed light theme: an editorial cream canvas with printed-poster motifs is the brand. This needs an explicit owner confirmation, written down once, so the decision is recorded rather than assumed.

### V-22 — The global focus rule hard-codes a 4px radius
- **Component:** base layer
- **File:** `src/app/globals.css:137`
- **Problem:** `:focus-visible { border-radius: 4px }` sits in the base layer. The utilities layer wins, so every element with a `rounded-*` utility is currently unaffected, but any future focusable control that relies on inherited rounding will be squared off. The declaration is also redundant: browsers shape the outline with the element's own radius.
- **Rule:** R-32, R-39
- **Improvement:** delete the `border-radius` line from the focus rule.

### V-23 — The homepage title repeats the brand suffix
- **Component:** metadata
- **File:** `src/app/layout.tsx:31`, `src/app/(public)/page.tsx:18`
- **Problem:** the root template is `%s - ngantuqan` and the homepage sets its own title to "ngantuqan - Creative Design Studio". The rendered `<title>` is "ngantuqan - Creative Design Studio - ngantuqan", measured in the live DOM. The other five routes render correctly.
- **Rule:** R-31 (a decision with no reason), R-20
- **Improvement:** set the homepage title to the bare "Creative Design Studio" so the template supplies the brand.

### V-24 — Two grid rows leave a 429px hole
- **Component:** Selected Works, Services Overview
- **File:** `src/components/home/selected-works.tsx:26-41`, `src/components/home/services-overview.tsx:17-21`
- **Problem:** measured at 1440px, the second row of the Selected Works grid uses 763px of 1192px (4 of 12 columns empty, 429px hole) because cards 3 and 4 are `lg:col-span-4`. The Services Overview grid leaves the same 429px hole because five cards sit in a three-column grid. Both are visible gaps in the composition.
- **Rule:** not an antislop rule. Structural, and therefore approval-gated.
- **Improvement:** this cannot be fixed with styling alone. Either let the last card span the remaining columns, or reduce the section to the grid the content actually needs. Both are structural changes outside the hero, so they need the owner's approval before any edit.

### V-25 — Implementation drifts from the documented spec in three places
- **Component:** hero rhythm, CTA rhythm, header hairline

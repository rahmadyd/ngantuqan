# antislop audit 003 — ngantuqan (visual UX review)

- **Date:** 2026-11-13
- **Mode:** after (session override)
- **Scope:** public website, with emphasis on the homepage. Admin screens were excluded.
- **Direction read:** `DESIGN.md`, playful retro-nature editorial, ENERGY 3 / RHYTHM 1 / MOTION 2.
- **Method:** live app at `http://localhost:3130`, Playwright screenshots at 1440×1000 and 390×844, scripted interaction checks, keyboard and target-size measurements, code inspection, lint and typecheck.
- **Changes:** no `src/` or design files were modified. This report only records findings for owner approval.

## Verdict

**Good website, roughly 8/10 for the current public-facing refresh.** The brand is now distinctive, the cream/forest/terracotta system feels intentional, the hero illustration creates a memorable entrance, and the card grids remain easy to scan. The homepage does not need another redesign.

The main remaining weaknesses are not aesthetic. They are focus management, contrast and tap-target details around the mobile header and hero, plus incomplete loading and empty states. Fixing those will raise the experience more than adding more decoration.

## HIGH — Hard Gate

### A-01 — Mobile menu does not move or trap focus

- **Component:** mobile navigation dialog
- **File:** `src/components/layout/site-nav.tsx:74-165`
- **Measured:** after opening the menu, focus remained on **Open menu**. The next Tab moved to a background link (`A`), not the first item inside the dialog. The dialog contains 9 focusable controls, but background content remains keyboard reachable.
- **Rule:** R-32, R-39
- **Reason:** an `aria-modal` dialog must receive focus, keep Tab inside itself, and restore focus to the trigger when closed.

### A-02 — Hero image is a CSS background, not a prioritized HTML image

- **Component:** homepage hero artwork
- **File:** `src/components/home/hero-section.tsx:65`, `public/assets/hero-bg.webp`
- **Problem:** the LCP candidate is loaded through `bg-[url('/assets/hero-bg.webp')]`. It is not represented by an HTML `<img>`, so it cannot declare intrinsic dimensions, `fetchpriority="high"`, or an explicit fallback relationship to the headline.
- **Rule:** R-40
- **Reason:** the hero is the most important visual and should be explicitly prioritized in the document head and first paint.

### A-03 — Hero headline contrast is not proven against the image

- **Component:** homepage H1 and hero overlay
- **File:** `src/components/home/hero-section.tsx:65-95`
- **Problem:** the headline fill is `#FFF9EC` and the asset contains near-white clouds. The dark 2.5px stroke improves shape recognition, but the fill-to-background contrast still needs to be measured across the complete text area. The existing contrast table only covers solid tokens and does not test text over imagery.
- **Rule:** R-25
- **Reason:** large text needs a minimum 3:1 contrast against every background region it crosses.

## MEDIUM — Purpose-Gate

### A-04 — Several mobile controls are below the 44px touch target

- **Component:** locale toggle, menu trigger, cart, header CTA and hero contact link
- **File:** `src/components/layout/locale-toggle.tsx:73-81`, `src/components/layout/site-nav.tsx:90-98`, `src/components/shop/cart-link.tsx:21-30`, `src/components/ui/button-link.tsx:26-30`, `src/components/home/hero-section.tsx:113-118`
- **Measured:** locale flags are 28×28px; menu and cart triggers are 40×40px. Header and inline text links also have heights between 18px and 36px.
- **Rule:** R-03, R-39
- **Reason:** the controls are visually small, so their hit areas need extra padding rather than a visible size increase.

### A-05 — Empty homepage data silently removes sections

- **Component:** Selected Works, Services, Products and Testimonials
- **File:** `src/components/home/selected-works.tsx:8-10`, `src/components/home/services-overview.tsx:6-8`, `src/components/home/products-preview.tsx:7-9`, `src/components/home/testimonials.tsx:5-11`
- **Problem:** each component returns `null` when its dataset is empty. A valid but unpopulated database makes four sections disappear without explanation or recovery guidance.
- **Rule:** R-27
- **Reason:** an empty state should explain what is missing and offer the nearest useful destination.

### A-06 — Public loading state is generic and silent for assistive technology

- **Component:** route-level public loading UI
- **File:** `src/app/(public)/loading.tsx:10-44`
- **Problem:** the skeleton resembles a generic heading-and-card layout rather than the homepage or catalogue being loaded. It also has no `role="status"`, `aria-busy`, or live announcement.
- **Rule:** R-27, R-39
- **Reason:** loading feedback should preserve the expected composition and announce progress without relying on animation alone.

## LOW — Quality Locks

### A-07 — Hero copy is generic and not fully localized

- **Component:** hero title and primary CTA
- **File:** `src/lib/i18n/dictionaries/en.ts:57-67`, `src/lib/i18n/dictionaries/id.ts:60-70`
- **Problem:** the H1 is **Welcome** in both locales, which is generic and does not describe the studio's offer. The English primary CTA remains **JELAJAHI**, even though the surrounding page is English.
- **Rule:** R-16, R-20
- **Reason:** the first screen should state what the studio does in memorable, locale-appropriate language. `DESIGN.md` explicitly requests JELAJAHI, so translating it requires an owner decision rather than a silent change.

### A-08 — `overflow-x: hidden` can conceal future clipping

- **Component:** global body rule
- **File:** `src/app/globals.css:137-143`
- **Problem:** the body clips horizontal overflow. The measured pages currently have 0px overflow, but the rule can hide the exact regression it is meant to prevent.
- **Rule:** R-03, R-35
- **Reason:** responsive verification is more reliable when overflow remains visible to the browser and test runner.

### A-09 — `HeroNatureArtwork` is a dead component

- **Component:** unused hero illustration component
- **File:** `src/components/home/hero-artwork.tsx:1-10`
- **Problem:** the component always returns `null`, is not imported, and conflicts with the current implemented hero direction.
- **Rule:** R-31, C-2
- **Reason:** remove dead implementation or make its ownership and purpose explicit so future work does not build on an abandoned direction.

## What already works

- **Visual identity:** the hero illustration, warm cream canvas, forest ink and terracotta accent are distinctive and coherent.
- **Hierarchy:** each homepage section has one clear heading role, and the section order remains easy to understand.
- **Responsive composition:** no horizontal overflow was measured at 1440×1000 or 390×844 on the reviewed public pages.
- **Interaction completeness:** mobile menu opens and closes with Escape, work filters update the URL, search filters results, and add-to-cart gives immediate feedback.
- **Console health:** the scripted public interaction pass reported no console or page errors.
- **Code health:** `npm run lint` passed and `npm run typecheck` passed.

## Recommended order

1. Fix A-01 and A-04 first. They are contained accessibility changes with immediate mobile benefit.
2. Measure and fix A-03, then convert A-02 to an explicit, prioritized hero image.
3. Add honest empty and accessible loading states for A-05 and A-06.
4. Decide the final hero wording for A-07.
5. Clean up A-08 and A-09 during the next maintenance pass.
